# 第 9 章：设计网络爬虫

## 引言
**网络爬虫（web crawler）**，也称蜘蛛（spider）或机器人（robot），用于发现并采集网页、图片、视频等网络内容。本章聚焦于为**搜索引擎索引**设计一个可扩展的网络爬虫。

### 网络爬虫的应用
1. **搜索引擎索引：** 采集网页以创建可搜索的索引（例如 Googlebot）。
2. **网页存档：** 为将来使用而保存网络数据（例如美国国会图书馆）。
3. **网络挖掘：** 从网络数据中提取知识（例如对股东报告做财务分析）。
4. **网络监控：** 检测版权或商标侵权。

### 设计挑战
一个好的网络爬虫必须解决以下问题：
- **可扩展性：** 通过并行化处理数十亿个页面。
- **健壮性：** 应对糟糕的 HTML、崩溃和恶意链接。
- **友好性（politeness）：** 避免因请求过多而压垮服务器。
- **可扩展性（extensibility）：** 以最小改动支持新的内容类型。

---

## 第 1 步：理解问题

### 需求
1. 每月爬取 **10 亿个网页**（400 页/秒，峰值 800 QPS）。
2. 只采集**纯 HTML 内容**。
3. 跟踪新增与更新的页面。
4. 忽略重复内容。
5. 爬取的数据保留 **5 年**，约需 30 PB 存储。

## 第 2 步：高层设计

### 组件

1. **种子 URL（Seed URLs）：** 爬虫的起始入口。
    - 需要精选出一个好的起点，使爬虫能够借此遍历尽可能多的链接。
    - 可以基于不同热门网站的地域分布，或基于主题来选取。
    - 策略：按地域或主题分类（例如体育、医疗）。

2. **URL 队列（URL Frontier）：** 存放待下载的 URL。
   - 以 **FIFO 队列**的形式实现。

3. **HTML 下载器（HTML Downloader）：** 从 URL 队列提供的 URL 下载网页。

4. **DNS 解析器（DNS Resolver）：** 把 URL 转换为 IP 地址。

5. **内容解析器（Content Parser）：** 校验并解析网页。
   - 丢弃格式错误的页面。

6. **内容去重检查（Content Seen?）：** 使用哈希比较检查重复内容（比较两个网页的哈希值）。

7. **内容存储（Content Storage）：** 把 HTML 页面存到磁盘上（热门内容放在内存中以降低延迟）。

8. **URL 提取器（URL Extractor）：** 从解析后的页面中提取新链接。

9. **URL 过滤器（URL Filter）：** 排除黑名单或错误的 URL。

10. **URL 去重检查（URL Seen?）：** 跟踪已访问过的 URL，避免重复。

11. **URL 存储（URL Storage）：** 存放已经访问过的 URL。


---

### 工作流程
1. 把**种子 URL**加入 URL 队列。
2. **HTML 下载器**抓取 URL，并通过 DNS 解析器解析其 IP。
3. **内容解析器**校验内容，并把内容传给「内容去重检查」组件。
4. 如果内容是新的，则通过 **URL 提取器**提取链接。
5. 过滤后把不重复的链接加入 URL 队列。

## 第 3 步：关键组件深入剖析
### DFS/BFS
- 可以把 Web 看作一张有向图：网页是节点，超链接（URL）是边。
- 图遍历通常使用 BFS（广度优先搜索），因为深度可能非常深，所以 DFS（深度优先搜索）并不理想。
- 标准 BFS 不考虑 URL 的优先级，而并非每个页面的质量和重要性都相同。


### URL 队列
- **友好性（Politeness）：** 
    - 确保同一时间对每个主机只发一个请求。在两次下载任务之间加入延迟。
    - 使用从主机名到队列和工作（下载）线程的映射。
    - 每个下载线程有各自独立的 FIFO 队列，并且只从该队列下载 URL。

        <img src="../../09.%20Web%20Crawler/images/politeness.png" alt="友好抓取" width="500">

    - **队列路由器（Queue router）：** 确保每个队列（b1, b2, … bn）只包含来自同一主机的 URL。
    - **映射表（Mapping table）：** 它把每个主机映射到一个队列。
    - **队列选择器（Queue selector）：** 每个工作线程映射到一个 FIFO 队列，并且只从该队列下载 URL。队列的选择逻辑由队列选择器完成。
    - **工作线程 1 到 N。** 一个工作线程按顺序从同一主机下载网页。两次下载任务之间可以加入延迟。

- **优先级（Priority）：** 
    - 给重要页面分配更高优先级（例如按 PageRank 或更新频率）。

        <img src="../../09.%20Web%20Crawler/images/prioritizer.png" alt="优先级排序" width="500">
    
    - **优先级排序器（Prioritizer）：** 它以 URL 为输入，计算优先级。
    - **队列 f1 到 fn：** 每个队列都有一个分配好的优先级。高优先级的队列被选中的概率更高。
    - **队列选择器：** 有偏向地随机选择队列，优先选择高优先级队列。
    - **前队列（Front queues）：** 管理优先级。
    - **后队列（Back queues）：** 管理友好性。

- **新鲜度（Freshness）：** 根据更新历史或重要性进行重新爬取。


### HTML 下载器
- **遵守 robots.txt：** 尊重 robots.txt 文件中的规则。
- **性能优化：**
  1. 使用多台服务器进行分布式爬取。
  2. 使用 **DNS 缓存**，避免重复查询。
  3. 按地理位置分布爬取服务器，以加快下载速度。
  4. 使用较短的超时时间，避免被缓慢或无响应的服务器拖住。

### 健壮性
1. **一致性哈希：** 在服务器之间有效地分发负载。
2. **错误处理：** 防止异常导致系统崩溃。
3. **数据校验：** 确保内容完整性。

### 可扩展性
- 为新的内容类型添加模块（例如 PNG 下载器、网页监控器）。
- 示例：插入一个模块来监控网页内容是否侵犯版权。

    <img src="../../09.%20Web%20Crawler/images/extensibility.png" alt="可扩展性" width="600">

### 规避问题内容
1. **重复内容：** 使用哈希比较来检测。
2. **蜘蛛陷阱（Spider Traps）：** 用 URL 长度限制等技术避免无限循环。
3. **数据噪声：** 过滤广告或垃圾内容等无关内容。

---

## 第 4 步：收尾总结
### 关键要点
1. 网络爬虫必须在可扩展性、健壮性、友好性与可扩展性之间取得平衡。
2. **友好性**防止压垮服务器，而**优先级**确保重要页面被优先爬取。
3. 高效的存储与错误处理对于处理大规模爬取至关重要。

### 其他考量
- **服务端渲染：** 处理由 JavaScript 或 AJAX 生成的动态内容。
- **反垃圾措施：** 排除低质量或无关页面。
- **数据库分片：** 使用复制与分片扩展数据层。
- **水平扩展：** 使用无状态服务器高效扩展爬取任务。
- **数据分析：** 采集并分析数据，以获取洞察。
